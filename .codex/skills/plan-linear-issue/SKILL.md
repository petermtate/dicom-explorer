# Plan Linear Issue

## Use this skill when
- The task begins from a Linear issue
- Requirements are vague or need structuring
- A coding task needs a clean implementation plan before execution

## Goals
Turn the issue into:
1. problem statement
2. acceptance criteria
3. non-goals
4. likely files/systems affected
5. implementation plan
6. risk list
7. validation plan

## Process
1. Restate the issue in plain language.
2. Extract explicit requirements.
3. List assumptions separately.
4. Define non-goals to prevent scope creep.
5. Identify likely files, modules, routes, APIs, tables, or configs involved.
6. Propose the smallest implementation plan that satisfies the issue.
7. Define validation:
   - tests to add or update
   - manual checks
   - preview checks if applicable
8. Stop and present the plan before major implementation.
